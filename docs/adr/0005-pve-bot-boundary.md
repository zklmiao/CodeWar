# ADR-0005：PvE 模拟对手（Bot）的接入边界

**状态**：已接受（09 号票，2026-10-21）。
**关联**：Spec 用户故事 32-33、开放问题 3；设计 002 §5（seed 派生）；ADR-0002（事件流同步）；ADR-0004（判题结构契约）

## 背景

单人 PvE 练习需要一个由服务端驱动的模拟对手。核心约束来自 spec「三 Seam」与反作弊底线：

- MatchEngine 是唯一集成 seam，玩家行动只能经 SubmissionPort（`engine.Submit`）进入；
- 引擎不得为某类玩家开特殊路径——否则"Bot 与真人同一套规则"无法测试、也无法审计；
- 出题必须与 PvP 完全同源（同一 `question.Config`、同一 matchSeed 派生），PvE 不能成为绕过题目/难度配置的后门；
- 参考答案（AnswerKey）只能存在于服务端内部，任何下行消息都不得携带。

## 决策

**Bot 是 hub 层的独立组件（`server/internal/bot.Controller`），对引擎零侵入。**

1. **唯一行动接入面**：Bot 与真人客户端一样经 `engine.Submit` 提交；目标选择经 `engine.SetTargeting`（真人同款免费操作）；观测只用 `engine.Snapshot`。`match` 包内不存在任何 bot 相关标识符或分支，由 `bot` 包的 grep 结构测试钉住。
2. **共享出题工厂与 seed**：hub 为 PvE/PvP 走同一条 `newQuestions` 构造路径；Bot 持有同一 `QuestionPort` 实例，按 `(round, player)` 重新取题即可确定性再生本回合同题。正确分支提交 `Question.AnswerKey`；错误分支提交 `starter`，走真实判题失败（自损 3 + 锁 5s，与真人同规则）。
3. **事件接入不侵入引擎**：Bot 通过 hub 广播路径追加的 observer 获知 `RoundStarted`。广播发生在引擎锁内，因此 observer 只做"采样 + 调度"（时钟 `AfterFunc`），真正的 `Snapshot`/`Submit` 在定时回调里执行；新回合会取消上一回合未触发的行动，陈旧行动在提交前按快照回合号丢弃。
4. **AnswerKey 是服务端内部字段**：`match.Question` 新增 `AnswerKey`，出题工厂填充；`Problem` proto 不含该字段，`problemToPb` 不下发。引擎忽略它——提交参考解与提交任意代码走同一判题路径。
5. **职业盲选复用 06 号票机制**：Bot 职业与技能按 matchSeed 确定性选取（`bot.Loadout`），开局前绑定到引擎；快照的盲选规则在开局前隐藏对方职业，开局揭示。`PlayerView.bot` 由 hub 在快照上标注（引擎不感知）。
6. **难度参数集中**：三档初稿（耗时窗/正确率/行动权重）定义在 `bot.ParamsFor`。数值属 spec 开放问题 3（待 playtest 标定），只改该表。技能冷却中其权重并入攻击。
7. **生命周期归 hub**：PvE 单连接断开即对局作废（`Engine.Stop` 幂等、不广播 MatchEnded），刷新重开；通用重连/在线匹配归 08 号票。PvE 不落战绩/ELO（Bot 无账号，"双方认证才落库"规则的显式化）。

## 后果

- **(+)** Bot 的每次提交都必然产生正常判题事件；引擎测试与 PvE 共用同一路径，无"测试专用旁路"。
- **(+)** PvP 缺省链路（无 `mode` 参数）逐字节等价；PvE 只是把 p2 的行动提交者从 WebSocket 换成进程内调度器。
- **(+)** 出题同源：PvE 与 PvP 的题型/cap/策略/seed 派生由同一函数产出，配置 UI 直接复用 05 号票。
- **(−)** Bot 与引擎之间存在一个微小的"跨回合提交"竞态窗口（快照校验后、Submit 前对局若恰好切回合）。与真人客户端面对的网络竞态同类，由 hub 的单连接串行拓扑与回合长窗口把实际概率压到可忽略；不为此在引擎内加特判。
- **(−)** 三档数值未经 playtest 标定，当前只保证"更快/更准"的方向性与测试可复现。

## 备选方案（被否原因）

- **引擎内置 Bot 分支**：违反"Bot 与真人同一套规则"的可测试性，且把模拟对手的生命周期耦合进对局状态机。否决。
- **Bot 作为第二个 WebSocket 客户端回环接入**：拓扑上最"无特判"，但需要服务端自连本机、引入网络抖动与重连语义，且 PvE 的断线作废规则会与通用重连纠缠。否决。
- **Bot 直接调用引擎内部结算/绕过判题**：产生"跳过判题"的旁路，无法证明 Bot 与真人同规则。否决。
