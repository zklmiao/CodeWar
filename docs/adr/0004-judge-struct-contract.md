# ADR-0004：判题契约 v2——结构体类题的 setup/compare 声明

**状态**：已接受（15 号票）
**关联**：ADR-0003（一次性容器沙箱）、设计 002 §3/§5、票据 15

## 背景

题库扩容（12 号票）需要引入输入/输出为结构体的题目（链表 12、树 8、LRU、用栈实现队列，约 20 道）。现行判题契约只支持"函数吃标量/数组、吐标量/数组"：`Call` 是 Python 表达式（在玩家命名空间 eval），`Expected` 是期望 repr 字符串（宿主侧字符串比对）。`ListNode`/`TreeNode` 无法用表达式字面构造，`repr(结构体对象)` 是含内存地址的非规范化串，宿主无法比对。

## 决策

**契约形态 =「题侧声明，沙箱执行，宿主比对」**：TestCase 新增两个可选字段（空串 = 未声明，走现行路径，字节级向后兼容）：

- **setup**：题作者 Python 代码，在 worker 内于玩家代码 import 之后、`call` 求值之前 exec 进玩家命名空间副本；可用沙箱构造辅助库（`list_to_nodes` / `build_tree` / `make_cycle` 等，随 payload 注入），为 call 绑定结构体入参。
- **compare**：`def _normalize(got): ...` 的完整函数源码。worker 在求值成功后用它把 got **规范化为 repr 字符串**（链表→"[1,2,3]"；环入口→"cycle:[2,0,-4]"——按 id 走环的有界遍历，对唯一值测试数据即节点身份的规范化表达）；宿主对规范化串做字符串等价比对。

**不变量（与现行协议逐字一致）**：expected 永不进容器；worker 只回传规范化 repr 字符串；值比对在宿主；detail 白名单不变。

**信任边界变化（本 ADR 的核心记录）**：setup/compare 是**题作者代码**，将进入沙箱容器执行。这是对"容器内只跑玩家代码 + 系统注入 harness"的扩展。处理：注入前过与玩家代码同级的静态卫兵（长度上限 4000、禁用调用清单 open/__import__/subprocess/os.system/shutil/importlib/eval/exec、必须可编译）；运行期崩溃归因 infra（judge-error），绝不罚玩家；真实边界仍是沙箱本身（断网 + 配额 + 只读根 + 每用例超时）。

## 否决项

1. **比较挪到宿主（worker 只回传原始结构）**：需要把链表/树/环序列化跨容器传回并在宿主重建——要么把序列化器也注入容器（等价于本方案多一层），要么破坏"expected 不进容器、结构不跨边界"的零泄漏协议。否决。
2. **JSON Schema 式声明式比较器**：表达不了"按节点身份比较环入口"（142 题核心语义）与任意规范化规则；表达力不足。否决。
3. **setup 在玩家代码 import 之前执行**：有状态类（LRU/MyQueue）的构造需要玩家定义的 `Constructor`——时序上必须 import 后。否决。
4. **per-step 早期终止的调用序列协议**（为 LRU 类新增逐方法步进事件）：调用序列用"求值结果为每步返回值列表"的单表达式即可表达（`[obj.put(1,1), obj.get(1), ...]`），expected 为整串 repr——零协议新增，verdict 完全等价（wrong-answer），放弃逐步 early-stop 的可观测收益（detail 本来就是空的）。否决步进协议。

## 与提示词裁决的精化说明

票据提示词裁决 1 原文写 compare 签名为 `(got, expected)→bool`。落地时发现：bool 语义要求 expected 进容器或在容器内重建期望结构，与同一裁决自述的理由（"值比对仍在宿主""泄漏面与现行协议完全一致"）冲突。故精化为**规范化器 (got)→canonical-repr**，bool 等价由宿主字符串比对给出。此精化忠实于裁决的安全不变量。

## 后果

- **(+)** 约 20 道结构体题（链表 12、树 8、LRU、用栈实现队列）具备入库条件；`Call/Expected/setup/compare` 四元组即 12 号票的题目格式范例（见设计 002 附录 E）。
- **(+)** 向后兼容字节级成立：空串声明走现行路径，现役 26 模板与全部既有测试零改动全绿。
- **(−)** 题作者代码进容器扩了信任边界——依赖静态卫兵 + 沙箱兜底；卫兵清单是黑名单，理论上存在绕过面，靠沙箱运行时约束（断网/配额/只读/超时）兜住。
- **(−)** 规范化 repr 的环身份语义依赖"测试数据节点值唯一"假设（唯一值下旋转序列即身份）；非唯一值环的身份比较需要 id 传递机制，留待真实题目出现时扩展。

## 观测记录

样题判题延迟（真实容器）：正常判题 ~120-450ms（含容器启动）；每用例超时语义不变（构造+执行同受 PER_TEST_TIMEOUT 约束）。
