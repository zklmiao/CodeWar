# Spec 001: CodeWar（代码战争）MVP

> **Labels**: `ready-for-agent`
> **状态**: 已确认（设计共识文档 v0.1，2026-10-03 grilling 会话产出）
> **参考**: `ref_resources/`（CodeCombat 源码与 The Farmer Was Replaced 拆解，仅作创意参考，不构成实现依赖）

## 问题陈述

学过 Python 基础（3-12 个月）的学习者面临"练习动力断崖"：刷题平台（LeetCode 类）有压力但无游戏性，编程游戏（CodeCombat 类）有游戏性但缺乏真人对抗的张力。学习者需要一个**把解题能力直接转化为对抗胜负**的场景——赢得靠代码写得又对又快，输得心服口服，且每一局都在真实题目上练功。

## 解决方案

CodeWar 是网页端 Python 编程对抗游戏：两名玩家在 5×5 网格竞技场上各控制一个角色，进行 1v1 回合制答题对战。每回合系统同时展示多道代码题（攻击/移动/防御/技能），玩家**自选一道**在倒计时内作答，解出哪道就执行对应行动：攻击向对手开火（同题镜像竞速，越快伤害越高）、移动实现走位闪避、防御获得减伤、技能释放职业专属大招。全部测试用例通过行动才生效，HP 归零者败。

开局选择"题型 + 最高难度"，实际出题在 [最简单, 所选上限] 区间抽取，且所选难度越高伤害与奖励系数越高——难度选择本身是风险回报决策。

MVP 包含：交互式教程（3-5 关）、1v1 PvP、单人练习 PvE（模拟 Bot）、3 个职业、6 大题型、5 档难度、可配置抽题策略（均匀/爬坡）、ELO 段位分。

## 用户故事

**账号与匹配**

1. As a 注册玩家, I want to 创建账号并登录, so that 战绩与段位能跨对局保留
2. As a 注册玩家, I want to 查看历史对局记录与胜率, so that 追踪自己的成长轨迹
3. As a 注册玩家, I want to 看到 ELO 段位分及其变化, so that 有明确的排位目标感
4. As a 注册玩家, I want 系统按段位就近匹配对手, so that 每局都有挑战且公平

**新手教程**

5. As a 新玩家, I want 3-5 关交互式教程依次教我 读题作答→走位闪避→防御与技能冷却→难度收益, so that 不读任何文档就能学会玩法
6. As a 新玩家, I want 完成教程后才解锁 1v1 匹配入口, so that 不至于在不懂规则时被推入正式对局被碾压

**对局配置**

7. As a 玩家, I want 开局从 6 大题型（语法与运算/字符串处理/数组与列表/哈希与计数/排序与贪心/递归与简单DP）中选择一种, so that 对抗发生在我擅长或想练的知识领域
8. As a 玩家, I want 开局选择最高难度档（L1~L5）, so that 控制本局题目的挑战上限
9. As a 玩家, I want 所选难度上限越高、全局伤害与结算奖励系数越高, so that 主动拉高难度冒险有回报
10. As a 对局创建者, I want 设定抽题策略为 均匀随机 或 对局爬坡（从低档逐回合逼近上限）, so that 选择适合我的节奏风格

**回合循环**

11. As a 玩家, I want 每回合同时看到 攻击题/移动题/防御题 + 已装备技能位（冷却中灰置）, so that 我能横向比较后决策本回合行动
12. As a 玩家, I want 攻击题是双方同一实例的镜像题, so that 竞速绝对公平、复盘可比较
13. As a 玩家, I want 我的提交只有全部测试用例通过才生效, so that 半对的代码骗不到伤害
14. As a 玩家, I want 提交错误答案时被锁定 5 秒并自损 3 HP, so that 无脑暴力试错有代价
15. As a 玩家, I want 解题耗时越短行动收益越高（时间系数 0.6~1.0）, so that 熟练度直接转化为战斗力
16. As a 玩家, I want 回合结束时按完成耗时先后排序结算双方行动, so that 先解出者先手
17. As a 玩家, I want 一回合内只能解一道题（一个行动）, so that 每回合都是一次取舍决策
18. As a 玩家, I want 没解出任何题时本回合无法行动, so that 攻防有真实的空窗与追赶机会

**战斗动作**

19. As a 玩家, I want 解出攻击题后角色向对手攻击（基础伤害 22）, so that 把解题速度转化为输出
20. As a 玩家, I want 攻击有形状与射程（普攻=职业形状）, so that 站位成为博弈的一部分
21. As a 玩家, I want 解出移动题后在 5×5 网格上移动 1-2 格（正交方向）, so that 逃出对方攻击覆盖格即闪避成功
22. As a 玩家, I want 解出防御题后本回合获得 60% 减伤, so that 能硬接对方的关键一击
23. As a 玩家, I want 解出技能题后释放角色专属技能（伤害 42 / 治疗, 冷却 3 回合, 技能题难度=所选上限档）, so that 有高风险高回报的爆发手段
24. As a 玩家, I want 技能处于冷却时技能题位灰置不可选, so that 技能节奏有约束、build 有节奏感

**胜负判定**

25. As a 玩家, I want 一方 HP≤0 即负、双方同时归零判平, so that 结果清晰无争议
26. As a 玩家, I want 对局总时长耗尽时按剩余 HP 判定胜负, so that 对局必然出结果、不会无限拖

**出题系统**

27. As a 玩家, I want 每道题的难度都落在 [L1, 我选的上限] 区间内, so that 永远不会遇到超纲题
28. As a 玩家, I want 攻击题在"补全函数体"与"填空 1-3 行"两种形式间出现, so that 对局节奏有快慢变化
29. As a 内容作者, I want 按（题型 × 难度档 × 动作类型 × 题面形式）四维标注模板并定义参数槽位, so that 系统能从一个模板生成无限实例
30. As a 内容作者, I want 模板实例化时随机化数值/变量名/情境, so that 背答案彻底无用
31. As a 系统, I want 出题由 seed 确定性驱动（同 seed 同实例）, so that 测试可复现、反作弊可审计

**PvE**

32. As a 玩家, I want 单人练习模式对抗模拟 Bot（按难度配置解题耗时分布与正确率）, so that 零压力练手并测试 build
33. As a 玩家, I want PvE 同样可选 题型 + 最高难度, so that 练习有针对性

**职业**

34. As a 玩家, I want 3 个初始职业（剑士/法师/游侠）拥有不同的技能集与攻击形状, so that 存在真正的 build 差异与相性博弈
35. As a 玩家, I want 对局前将 1 个主动技能装备进技能槽, so that 每局都是一次构筑决策

**反作弊**

36. As a 玩家, I want 对局内是锁定沙箱编辑器（禁粘贴、禁外部工具）, so that 对手无法靠 AI 外挂降维打击
37. As a 管理员, I want 系统对答题节奏异常、粘贴行为指纹进行检测并标记违规, so that 天梯排名可信

## 实现决策

**架构：三 Seam（已与需求方确认）**

- **MatchEngine（对局引擎，唯一集成 seam）**：回合状态机（回合开始→面板组装→作答窗口→结算→回合结束）。依赖三个端口：`QuestionPort`（按 动作类型+难度区间+题型 取题）、`SubmissionPort`（玩家提交流：真人经网络接入、脚本回放用于测试、PvE Bot 亦由此进入）、`ClockPort`（回合计时，测试中可加速）。引擎对外只发布**对局事件流**（回合开始/面板就绪/提交判定/行动结算/HP 变化/对局结束）。全部战斗规则在该边界内实现。
- **Judge（判题器，纯函数 seam）**：`judge(code, testCases) → {passed, durationMs}`。沙箱执行（禁网络、资源与时间上限、超时判负）；100% 用例通过才算通过。
- **QuestionFactory（出题工厂，纯函数 seam）**：`create(spec, seed) → {instance, answerKey, testCases}`。spec 含（题型×难度档×动作类型×题面形式）；**seed 确定性**是测试复现与实例随机化反作弊的共同地基。

**战斗规则**

- 同步回合制：固定倒计时（75 秒，待调参），双方各选一题作答，回合结束按完成耗时排序统一结算。
- 伤害公式：`基础伤害 × 时间系数（0.6~1.0，完成越快越高） × 难度系数（L1 ×0.85 → L5 ×1.20） × 形状命中判定 × 防御减伤`。攻击同题竞速的"耗时越短伤害越高"由时间系数承载。难度系数自 05 号票起生效：01 范围内无难度输入（难度选择 UI 归 05、题目难度归 04），01 实现暂为`基础 × 时间系数`（见 01 票尾部"已知偏差记录"）。
- 攻击形状建模为**格子偏移集合**（线性覆盖相对攻击者朝向），普攻形状由职业定义（剑士=相邻正交 4 格邻域、方向无关；法师=直线深度 2；游侠=1-3 点狙），技能形状由职业定义（十字/3×3 等）；结算时 defender 位置不在覆盖格内 = 闪避成功。
- 网格 5×5 起步（7×7 预留），移动 1-2 格正交。
- 职业差异 = 技能集 + 攻击形状（+ 后续基础属性）。MVP 3 职业：剑士（近战高伤）/ 法师（远程范围）/ 游侠（机动）。
- 错误提交：锁定 5 秒 + 自损 3 HP，可继续作答。
- 胜负：HP≤0 即负；双方同时归零平局；总时长耗尽按剩余 HP 判定。

**出题系统**

- 模板按四维标注（题型 × 难度档 × 动作类型 × 题面形式），含参数槽位；实例化随机化数值/变量名/情境。
- 5 档难度标尺：L1 ≤30s 单语法点 / L2 ~45s 语法组合 / L3 ~60s 单一算法思想 / L4 ~90s 思想+边界 / L5 ~120s 多思想组合。难度档同时绑定预期解题耗时与考点深度。
- 抽题策略为对局级设置：均匀随机 / 对局爬坡（开局低档、逐回合逼近所选上限）。
- 攻击题 = 共享镜像实例；移动/防御/技能题 = 双方各自私有实例（均在难度区间内抽取）。
- 题型选择只过滤共享攻击题；行动题跨题型抽取。
- Python 单语言；Judge 接口预留多语言扩展。

**平台与网络**

- Web（桌面浏览器优先）；服务端权威架构：判题在服务端、对局状态由服务端裁决，客户端只负责渲染与提交；对局实时同步走 WebSocket。
- 反作弊：锁定沙箱编辑器（禁粘贴）+ 实例随机化 + 答题节奏/粘贴行为指纹检测与违规标记。

## 测试决策

**只测外部行为，不测实现细节**——测试通过公共边界观察结果，引擎内部状态机结构可以随意重构。

- **MatchEngine（主战场）**：整场对局回放测试——注入 fake QuestionPort（固定题集）+ 脚本化 SubmissionPort（预设提交序列与耗时）+ 加速 ClockPort，然后**断言事件流序列**：结算顺序、时间系数伤害、形状命中与走位闪避、防御减伤、技能冷却灰置、错误惩罚、平局、超时判定。战斗规则的每条用户故事（13-18, 19-26）都对应至少一条事件流断言。**错误路径优先**：双方都未解出、断线、同时归零、提交后判题超时。
- **Judge**：给定代码+用例的输入输出测试；必须覆盖作弊向量：死循环（超时终止）、资源超限、尝试网络访问、部分通过（必须判失败）。
- **QuestionFactory**：同 seed 必出同实例（确定性）；spec 约束满足（难度 ∈ 区间、题型/动作/形式匹配）；参数随机化分布合理（多次实例化不退化为单值）。
- **Prior art**：greenfield 无既有测试；本 spec 的测试决策即测试基建的起点，测试框架选型随技术栈 ADR 确定。

## 范围外（Out of Scope）

- 双人合作 PvE（2v2 Bot）与 2v2 PvP —— v1.1 / v2
- PvE 战役与"通关解锁新职业/技能"管线 —— v2（MVP 三职业默认全解锁）
- LLM 题面情境皮肤、观战/回放、移动端、Python 之外的语言
- 商业化（本次玩法探索明确不含）
- 数值最终平衡（本 spec 数值均为待调参初稿）

## 附注

**领域术语表**（后续票据与代码统一使用）：对局 Match / 回合 Round / 题面板 Panel / 行动 Action（攻击·移动·防御·技能）/ 镜像题 Mirror Problem / 难度档 Difficulty Tier（L1-L5）/ 抽题策略 Draw Strategy（均匀·爬坡）/ 结算 Resolution / 时间系数 Time Coefficient / 难度系数 Difficulty Coefficient / 职业 Class / 技能槽 Skill Slot / 对局事件流 Match Event Stream。

**数值初稿**（全部待 playtest）：HP 100/100；回合 75s；普攻 22；技能 42（冷却 3 回合）；防御 −60%（仅当回合）；移动 1-2 格；错误锁定 5s + 自损 3 HP；难度系数 L1 ×0.85 → L5 ×1.20。

**开放问题**（不阻塞实现，实现中遇到需回到设计共识）：

1. 填空题与补全函数题的收益平衡（倾向填空伤害系数 ×0.85）
2. 控制类技能效果未定 → **MVP 技能效果限定为伤害型与治疗型**，控制型待补充设计
3. PvE Bot 解题耗时分布标定
4. 模板产量：MVP 约需 6 题型 × 5 难度 × 4 动作形式 ≈ 120+ 模板，为最大内容工程
5. 抽题策略默认值（建议爬坡）需 A/B 验证
6. WebSocket 对局同步的技术选型——**已决议**：ADR-0002（事件流同步模型）+ ADR-0001（gorilla/websocket + proto 契约）；协议细节归 08 号票
7. 美术风格与 IP
8. 平局时 ELO 处理（默认各 +0）
