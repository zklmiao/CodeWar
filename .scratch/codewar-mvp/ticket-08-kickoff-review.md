# 08 开工提示词草稿 · Review & Check 报告（code-review）

- **审查对象**：`ticket-08-kickoff-draft.md`（v0.1）
- **审查维度**：用户测试要求 4 条 + 开发要求 3 条 + 仓库实态符合性（票文/ADR/代码锚点逐一对碰）
- **审查方法**：全文逐节审查；对草稿引用的每个代码/测试锚点回到仓库核实；对 08 将依赖/触碰的既有测试面做虚假 pass 与过度测试专项审计；对已交付产物做漏做核对
- **结论**：草稿方向正确但存在 **2 处过度设计、2 处过度测试风险、2 处虚假 pass 防线缺失、4 处漏项、1 处事实漂移**——全部可修，修订后升级为正式稿（v1.0）。逐条见下。

## A. 测试要求逐条审查

### A1.「测试用例、测试场景合理，无过度测试」→ 草稿有 2 处过度测试

- **R-3｜浏览器 E2E 自动化越界**：草稿要求「两窗口匹配→整局→ELO 断言」做成自动化。核对：票面该条（"两台设备两个浏览器"）本就是**人工验收语义**；且 2026-10-27 验收已实证 IAB/跨窗 GUI 自动化在长会话下崩溃率高，自动化做这条只会产出脆弱测试。**修正**：自动测试收在 seam（matchmaker/hub 事件流断言 + client vitest 退避序列）；两设备 E2E 改为人工验收清单随票交付，由人执行。
- **R-11b｜测试时长与场景面控制缺失**：草稿未给"合理测试"划界（哪些必须测、哪些明确不测）。**修正**：正式稿增「测试边界」小节——匹配语义/重连连续性/判负路径/ELO 落库必测；网络抖动重放、多实例扩容、恶意流量等明确不测（超纲）；hub 既有真实时钟测试（~36s）为合理成本基线，新增测试不得再引入分钟级墙钟用例（判负等待用可注入时钟）。

### A2.「测试用例不存在虚假 pass」→ 草稿防线缺失（未成事实）

- **R-4｜缺硬性禁令**：草稿测试节未写明 spec「测试决策」的既有口径（事件流 seam、具体值断言、错误路径优先），也未禁止 mock 互证（用 mock 断言 mock 的配置式测试）。核对既有面：hub 9 个测试文件（4041 行）、client 12 spec 64 用例、match/elo/store——2026-10-27 验收全部 -race + DSN + 真容器绿，5 项数值断言抽查均为具体值断言，无 mock 互证 → **存量无虚假 pass 迹象**；风险只在新增测试。**修正**：正式稿写入测试硬约束（含"行为修复先写红测试再修"的红→绿证据要求，如退避单飞）。
- **R-4b｜-race 与生成产物门禁**：proto 双端生成后必须 `go build/test -race` + `pnpm test/build` 全绿才算 schema 定稿（防"生成通过=只跑了 protoc"的假门）。草稿未写明。**修正**：纳入阶段完成标准。

### A3.「过度测试/虚假 pass 的发现→分析→方案→修正→回归」→ 草稿缺流程（R-5）

草稿无既有测试的处置流程。**修正**：正式稿写入——实现中发现既有测试疑似虚假 pass/过度测试：先记录现象与锚点 → 呈报人 → 批准后修正 → 修正提交必须附全量回归证据（-race + DSN + vitest/build）；**未经批准不得顺手改任何既有测试**（对齐 31 号票"断言、期望值、用例集不变"惯例）。

### A4.「核对已交付产物，看有没有漏做或者不做」→ 草稿整节缺失（R-6）

核对结论（依据 2026-10-27 验收 + 本日复点）：

| 项 | 结论 | 对 08 的处置 |
|---|---|---|
| 01-24、26-31 交付范围 | 无漏做（验收报告 37/37 矩阵；发现仅 F-1/F-2/F-4 三项 minor/major 均为独立问题） | F-1（inject_target 记录失实）、F-2（EndOverlay 认输文案）、F-4（风格页部署缺失）**均不进 08**，各需独立小票，08 内禁止顺手修 |

**修正**：正式稿增「开工前已核对基线」节，把上表固化为提示词的一部分。

## B. 开发要求逐条审查

### B1.「不过度设计」→ 草稿 2 处越界（R-1/R-2）

- **R-1｜匹配算法过度规定**：草稿把带宽/放宽节奏写成定值（±100、每 10s+50）。核对：spec 开放问题 5 明示抽题/匹配类默认值需 A/B，数值属调参面；定值写入提示词等于替代设计裁决。**修正**：语义固定（就近代价最小配对 + 随等待放宽），数值为**可调常量集中在 matchmaker 一处**，初值在开工呈报门由人裁决。
- **R-2｜队列持久化越界**：草稿自行加入「服务重启清空队列（注释记录）」尚可，但同类蔓延（持久化恢复、独立匹配服务、Redis、多实例）必须显式禁止。**修正**：正式稿设「范围外禁令」清单。

### B2.「业务逻辑覆盖必要场景」→ 草稿有遗漏场景（R-6b）

草稿覆盖了配对/重连/判负/ELO，但漏了四个必要场景：**排队中途退出/登出**（队列清理）、**匹配成功后一方拒绝或断线**（回池或作废的确定语义）、**双端同时重连竞态**（席位权威归属）、**排队时进入教程/PvE/热座的互斥**（单一在线会话约束）。**修正**：正式稿纳入阶段任务并各配事件流断言。

### B3.「符合开发 spec」→ 2 处对齐问题（R-7/R-8）

- **R-7｜票文漂移**：票文写「App.vue connect()」，实态在 `client/src/views/MatchView.vue:132-148`（已核：`setTimeout(connect, 500)` 无清理）。**修正**：提示词按实际位置下达，并注记票文漂移留待勾票时人确认（不擅自改票文）。
- **R-8｜裁决归属**：三项数值（判负等待时长、匹配带宽初值/放宽节奏、在线对局与教程/PvE/热座的互斥规则）spec 未定，属架构师/人裁决面。草稿自定值。**修正**：正式稿设「开工呈报门」——先呈报建议值与理由，获批后再实施。

## C. 其他发现

- **R-9｜仓库工作流约定缺失**：草稿未写 worktree/分支（`.worktrees/08-online-ranked-1v1`、`ticket/08-online-ranked-1v1`）、dev 端口（PORT=3008）、中文注释/英文 conventional commits、勾票归人（代理不改 Status）。**修正**：正式稿补「硬约束」节。
- **R-10｜33 号票预留缺失**：schema 定稿须为事件/对局落库（33 回放+错题本）留注释扩展点，只预留不实现。**修正**：纳入 P0 完成标准。
- **R-11a｜部署加固缺验收口径**：judge 非 root 化草稿只写"改非 root"。**修正**：完成标准=compose 起 judge 非 root + 全模板参考解冒烟（pytest 44 + templates 包）绿 + ADR-0003 同步修订。
- **R-12｜交付协议不完整**：code-review 报告应明确双轴（Standards/Spec，沿 27 号票惯例）+ 逐条票面验收汇报 + 回归证明清单。**修正**：纳入正式稿交付协议。

## D. 审查结论

草稿的问题全部为**提示词工程层**问题（范围划定/禁令缺失/裁决归属/事实漂移），不涉及对 08 交付方向的误判。按上表 R-1…R-12 修订后形成正式稿 `ticket-08-kickoff-prompt.md`（v1.0）。**无既有测试需要在本票实施修正**（存量审计无虚假 pass/过度测试迹象，证据见 A2/R-5）；正式稿以禁令 + 呈报流程防新增。
